# PostgreSQL for Python Backends

Applies to the Python + FastAPI + uv backend produced by `init-backend`.

## Stack

- PostgreSQL 16+
- SQLAlchemy 2.x with the async engine
- asyncpg as the driver
- Alembic for migrations
- pydantic-settings for configuration, already present
- pytest and pytest-asyncio for tests

## Dependencies

Run every command in this file from inside the backend directory.

```bash
uv add sqlalchemy[asyncio] asyncpg alembic
uv add --dev pytest-asyncio
```

## Configuration

Extend the existing `Settings` in `src/core/config.py`:

- `database_url: str` using the `postgresql+asyncpg://` scheme
- `database_pool_size: int = 5`
- `database_max_overflow: int = 10`
- `database_echo: bool = False`

Add to `.env.example`:

```text
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/app
```

Only require `database_url` once the database layer exists. Before this skill runs the backend works without it; keep that true for health tests by making the engine lazy.

## Engine and sessions

`src/db/engine.py`:

- `create_async_engine(settings.database_url, pool_size=..., max_overflow=..., pool_pre_ping=True, echo=...)`
- `async_sessionmaker(engine, expire_on_commit=False)`
- `async def dispose_engine()` called from the FastAPI lifespan shutdown
- Build the engine inside a cached factory function, not at module import.

`src/db/base.py`:

- `class Base(DeclarativeBase)` with a `MetaData(naming_convention=...)` so constraint names are deterministic and Alembic can drop them by name.

`src/api/deps.py`:

- `async def get_db_session() -> AsyncIterator[AsyncSession]` that yields a session and commits on success, rolls back on exception.

## Models

Do not create models. There are no tables yet.

Document for later: one module per table in `src/models/`, SQLAlchemy 2.x `Mapped` annotations, `DateTime(timezone=True)` everywhere, and every model imported in `src/models/__init__.py` so Alembic autogenerate sees it.

Set `target_metadata = Base.metadata` in `alembic/env.py` now. Add `import src.models` there when the user creates their first model.

## Migrations

Skip this section when native Supabase migrations were chosen. Do not install Alembic; follow `supabase-migrations.md` instead.


```bash
uv run alembic init alembic
```

Edit `alembic/env.py`:

- Read the URL from `src.core.config.get_settings().database_url`, not from `alembic.ini`.
- Set `target_metadata = Base.metadata` from `src.db.base`.
- Use the async runner pattern with `async_engine_from_config` and `connection.run_sync(do_run_migrations)`.
- Enable `compare_type=True` and `compare_server_default=True`.

Remove the hardcoded `sqlalchemy.url` from `alembic.ini`.

Do not create a revision during setup. Add these commands to the README for the user's first migration:

```bash
uv run alembic revision --autogenerate -m "<snake_case_description>"
uv run alembic upgrade head
uv run alembic downgrade -1
```

Review every autogenerated file before accepting it. Autogenerate misses renames and some constraint changes.

Never call `Base.metadata.create_all()` outside tests.

## Repositories

Do not create repositories now. Document for later: queries for each table go in `src/repositories/<table>.py`, taking an `AsyncSession`. Services call repositories. Endpoints never run queries.

## Readiness check

Add `GET /health/ready` next to the existing unversioned health endpoint:

- Execute `select 1` on a session from `get_db_session`.
- Return `200 {"status": "ok", "database": "ok"}` on success.
- Return `503 {"status": "degraded", "database": "unreachable"}` on `SQLAlchemyError`. Log the exception; do not return it.

Leave `GET /health` unchanged and database-free.

## Local development

Use the same `docker-compose.yml` as the Node.js reference: `postgres:16-alpine`, database `app`, user and password `postgres`, port 5432, a named volume, and a `pg_isready` healthcheck.

## Tests

- Configure `asyncio_mode = "auto"` for pytest-asyncio in `pyproject.toml`.
- `tests/db/test_connection.py` runs `select 1` against the real database from `DATABASE_URL`.
- Add a `conftest.py` fixture that skips the `tests/db` directory with `pytest.skip` when the connection fails.
- Existing health tests must not require a database.

## Verification

```bash
uv sync
docker compose up -d postgres
uv run alembic current   # connects, reports no revision
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run uvicorn src.main:app --reload --port 8080   # then request /health/ready
```

Confirm the readiness endpoint returns 200 with the database up and 503 with it stopped.
